# Papr Flutter Android 分阶段开发计划

> 状态：2026-08-24 按移动端适配分析重新收敛，可拆分为 Trellis 子任务执行
> 目标平台：Android 10+  
> 最终交付：可进入 Google Play 内测的 Release Candidate  
> 适用对象：负责 `papr-core`、Flutter Rust Bridge、Flutter UI、Android 平台集成和质量检查的 Agent

## 1. 目标与当前基线

当前 Flutter 应用只是可用性验证，已经具备以下最小闭环：

- 添加订阅源。
- 手动刷新订阅源。
- Feed 列表、文章列表、文章详情导航。
- 安全 HTML 正文与图片显示。
- 只读设置快照。

2026-08-20 已验证基线：

- `cargo test -p papr-core`：7 项测试通过。
- `cd mobile && flutter test`：2 项测试通过。
- `cd mobile && flutter analyze`：无问题。

最终 Flutter 应用以移动端高价值的数据与内容能力为目标，包括：

- 订阅源、文件夹、Feed 发现、OPML、手动与后台刷新。
- 智能视图、全文搜索、全文提取、阅读设置。
- 已读、收藏、稍后读、标签、规则、高亮、分享、浏览器打开。
- 翻译与 AI 摘要。
- Podcast 音频与 Android 后台播放。
- FreshRSS/Miniflux 同步，以及未来 Papr 多端同步所需的数据与接口基础。
- 本地化、后台刷新、通知与凭据安全。

范围以 `docs/desktop-mobile-porting-feature-analysis.md` 为准。桌面专属能力、低价值半成品和依赖鼠标/键盘/窗口的交互不进入移动端 RC；Android 必须提供的后台、媒体、通知与凭据能力按平台机制重新实现，不复用桌面运行时模型。iOS 保持可移植性，但不进入本计划验收矩阵。

### 1.1 明确不做

- 托盘、窗口状态、开机自启、Dock/任务栏角标、应用内自动更新、Tauri 子 WebView。
- 桌面快捷键、命令面板、hover 预览、右键菜单、桌面拖拽、专注模式、滚到底自动标已读、内嵌 YouTube iframe。
- Send to Kindle、AI Ask/RAG、AI Digest、Newsletter/IMAP、实验性内容去重。
- RSSHub 自建实例配置、存储统计/VACUUM、代理/并发度等高级运维设置不进入本轮 RC；已有基础 RSSHub URL 支持不回退。

## 2. 执行合同

### 2.1 固定架构方向

每项业务功能按以下垂直链路实施：

```text
桌面成熟逻辑 → papr-core → Tauri / FRB 薄适配器
                         → Flutter Repository / Riverpod → UI
```

- `papr-core` 是数据库、业务规则、网络协议和同步语义的唯一来源。
- Tauri 与 Flutter 适配器只负责参数、DTO、错误和事件转换。
- Flutter Widget 只依赖 Repository/Provider，不直接调用 FRB 生成 API。
- SQLite 与 HTTP 留在 Rust 层；Dart 不增加第二套数据库或网络业务实现。
- 继续使用现有 Riverpod、FRB 和 HTML 渲染栈，不引入第二套状态管理。
- 新依赖仅用于现有栈无法提供的 Android 原生能力：文档选择、系统分享/浏览器、Keystore、后台任务、通知和媒体会话。

### 2.2 阶段规则

执行顺序固定为：

```text
P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7
```

每个阶段都应作为可独立验证的 Trellis 任务；复杂阶段可按 Rust Core、FRB、Flutter UI 和 Android 集成拆成子任务。P0–P2 已完成，P3 已实现主体并进入收尾验收；P4–P7 按本次收敛后的范围重新建任务。下一阶段只能在当前阶段退出条件全部满足后开始。

每个实现任务必须：

1. 先读取本文件、相关代码和当前 Trellis 任务材料。
2. 记录该任务修改的公共 DTO、数据库迁移和事件契约。
3. 先在 `papr-core` 完成业务能力，再暴露 FRB，再接 Flutter。
4. 更新或新增最小但真实的回归测试。
5. 重新生成并提交 FRB 绑定；检查无非预期生成差异。
6. 运行任务相关检查及本文件第 7 节质量门禁。
7. 在任务交接中记录完成项、遗留项、风险和下一阶段入口。

## 3. 分阶段实施

## P0：统一核心与正式数据基线

### 实施内容

- 以桌面端完整数据库 schema 为依据，将迁移、DTO 和业务规则收敛到 `papr-core`。
- Flutter 验证版允许执行一次数据库重置，建立正式 Alpha schema；此后升级只能使用编号迁移。
- 保留 SQLite 整数 `id` 作为本地主键；可同步实体增加稳定 `sync_id`、`updated_at` 和删除标记。
- 增加事务内变更日志、provider 游标和远端 ID 映射。业务写入与变更日志必须同一事务提交。
- 建立类型化错误码；Rust 返回类别、代码和安全上下文，Flutter 负责本地化。
- 统一核心服务初始化、数据库路径注入、HTTP Client 配置和平台类型。
- 将 Flutter 代码按功能域组织；保留薄 Service/Repository 边界。
- 为 Tauri 逐步依赖 `papr-core` 建立入口，避免后续继续复制桌面逻辑。

### 退出条件

- 新装 Android 应用能初始化完整 schema。
- 现有桌面数据库能前向迁移且数据不丢失。
- Flutter Alpha 基线完成一次允许的数据重置；后续测试证明升级不再清库。
- FRB 生成可重复，生成前后无非预期差异。
- Tauri 与 Flutter 对核心 DTO、迁移和服务执行契约测试。
- 模拟业务写入失败时，业务数据和同步变更日志均回滚。

## P1：应用框架、订阅源与文件夹

### 实施内容

- 建立移动原生自适应导航：
  - 手机使用底部导航、抽屉/筛选面板和单栏详情跳转。
  - 平板使用 NavigationRail 和订阅/文章双栏布局。
  - 顶层入口固定为文章、订阅、已保存、设置。
- 接入简体中文、英文、日文，以及系统/浅色/深色主题。
- 完成文件夹创建、重命名、删除和排序。删除文件夹时 Feed 移到未分类，不删除 Feed。
- 完成 Feed 添加、删除、重命名、移动、单源刷新和单源刷新间隔。
- 添加订阅时复用桌面语义：
  - 支持 Feed URL、网页 Feed 发现和 `rsshub://`。
  - 支持 YouTube、Reddit、Mastodon、Bluesky、Podcast 来源识别。
  - 首次抓取、解析、分类和文章写入成功后再统一持久化。
  - 重复订阅、无效 URL、无 Feed、网络和解析错误使用稳定错误码。
- 提供订阅目录搜索和推荐。
- 通过 Android 系统文档选择器完成 OPML 导入、导出，不申请广泛存储权限。
- 增加 `papr://subscribe` 或 Android App Link 订阅入口。

### 退出条件

- Feed 与文件夹全部 CRUD 在重启后保持正确。
- 删除 Feed 前显示确认，删除后关联文章和缓存按约束清理。
- OPML 导入保留文件夹结构且不重复订阅；导出文件可重新导入。
- 离线、超时、证书错误和部分刷新失败不破坏本地已有数据。
- 手机和平板均无布局溢出，TalkBack 能识别主要控件。

## P2：文章列表、智能视图与完整阅读闭环

### 实施内容

- 提供全部、未读、收藏、稍后读，以及按 Feed、文件夹、标签筛选的智能视图和实时计数。
- 支持 `limit + offset` 分页、全文搜索、正序/倒序、隐藏已读和批量标记已读。
- 文章列表显示来源、标题、摘要、发布时间、缩略图和未读状态。
- 支持打开即标记已读、手动已读、收藏和稍后读；UI 乐观更新，失败回滚。
- 阅读器使用 `extracted_html` 优先、Feed 正文回退；支持安全 HTML、相对链接、懒加载图片和 enclosure。
- 完成全文提取、重新提取和自动全文设置。
- 完成字体、字号、行距、阅读宽度和阅读时长设置。
- 图片失败显示占位；正文链接交给外部浏览器。
- 通过 Android 系统分享面板分享标题与原文 URL；无 URL 时禁用分享和浏览器操作。
- 全文提取更新后清除旧翻译缓存。

### 退出条件

- 已读、收藏和稍后读变化能同步更新列表归属、计数与详情。
- 1 万篇文章数据下不会一次加载全部记录，滚动和筛选无明显阻塞。
- 恶意脚本、事件属性和不安全 URL 在 Rust 清洗层移除。
- 离线时可浏览缓存正文并执行本地整理操作。
- 浏览器、分享、返回导航、旋转和进程恢复通过真实设备测试。

## P3：标签、规则、高亮与个人整理

### 实施内容

- 完成标签创建、重命名、删除、颜色、排序及文章标签关联。
- 标签名称统一 trim，并按大小写不敏感规则防止重复。
- 完成过滤规则：
  - 匹配标题、作者、正文或任意字段。
  - 动作为跳过、标记已读、自动收藏。
  - 支持指定 Feed、启停、预览和应用到已有文章。
- 完成文章高亮、颜色、笔记、删除和全部高亮浏览。
- 收藏、稍后读、标签、规则和高亮变化写入同步变更日志。
- 文章清理必须保留收藏、稍后读或含高亮的文章。

### 退出条件

- 标签删除只清理关联关系，不删除文章。
- 规则预览与实际执行复用同一匹配逻辑。
- 高亮重新打开后可根据 quote、上下文和偏移重新定位；定位失败时保留记录并提示。
- 任一事务失败时不产生业务状态与同步日志的半写入。

## P4：翻译与 AI 摘要

### 实施内容

- 将现有 AI、翻译、HTML 分块和 SSE 解析逻辑从 Tauri 下沉到 `papr-core`。
- 沿用 BYOK：支持 Anthropic Messages 与 OpenAI Chat Completions 兼容端点。
- 支持多个 AI Profile、模型、Base URL、认证方式，以及按摘要/翻译指定默认 Profile。
- Profile 元数据存 SQLite；API Key 仅存 Android Keystore，不进入数据库、日志、备份或同步。
- 支持现有摘要模板、流式生成、重新生成、重试、取消和本地缓存。
- 翻译支持 LLM、Google、DeepL、Bing：
  - 按 HTML 块分批处理并保留结构。
  - 跳过代码、脚本和样式内容。
  - 流式报告批次进度。
  - 每篇文章缓存最近一次目标语言；切换语言时覆盖。
- AI 摘要与翻译结果默认不参与未来多端同步。

### 退出条件

- 模拟 HTTP/SSE 覆盖正常流、分片边界、中途错误、超时、取消和非法响应。
- 翻译后链接、图片、代码块和 HTML 层级保持正确。
- API Key 不出现在 SQLite、崩溃日志和用户错误消息中。
- 切换文章不会串用摘要或翻译进度。
- 无配置、无效密钥、限流和服务端错误均有可操作提示。

## P5：Podcast 与 Android 原生播放

### 实施内容

- 完成 Podcast 音频播放器：播放/暂停、进度、快退 15 秒、快进 30 秒、倍速和跨文章持续播放。
- 使用 Android 媒体会话和通知实现后台播放及锁屏控制。
- 补齐 Podcast 来源图标、音频 enclosure 展示规则和错误提示。
- 音频缓存仅按当前播放需要实现，不建设桌面式全局常驻运行模型。

### 退出条件

- 播放器在文章切换、锁屏、蓝牙控制和网络恢复后状态一致。
- Podcast 超时、损坏 enclosure 和网络恢复不会阻塞普通 Feed。
- 使用真实 Podcast 样本完成抓取、展示和播放回归。

## P6：后台刷新、通知与外部同步

### 实施内容

- 使用 Android 后台任务调度执行尽力而为的周期刷新。平台层只负责唤醒，`papr-core` 判断哪些 Feed 到期。
- 后台任务遵守网络、电量和系统限制；刷新间隔不承诺分钟级精确定时。
- 新文章通知支持权限、开关、夜间免打扰和批量汇总。
- 将 FreshRSS/Miniflux 同步下沉到 `papr-core`：
  - 同步订阅、文件夹、已读和收藏。
  - 本地变化进入可重试队列。
  - 拉取远端状态时不覆盖未成功推送的本地变化。
  - 显示连接、最近同步、错误和手动重试状态。
- 定义并用 Fake Provider 验证 provider-neutral `SyncPort`；本阶段不实现 Papr 账号和云服务。
- 第三方同步凭据只存 Android Keystore；数据库仅保存非秘密配置和凭据引用。
- 提供最小运维动作：手动刷新/同步、错误重试、重置设置和清除全部数据；不建设桌面高级运维面板。

### 退出条件

- 后台任务幂等，进程被杀后能从队列继续。
- 通知权限被拒绝不影响刷新。
- FreshRSS/Miniflux 在断网、部分失败和重复同步下不丢失本地操作。
- 清除数据同时删除数据库、缓存和 Papr 在 Keystore 中的凭据。
- Fake Sync Provider 完整演示 pull、push、ack、cursor、tombstone 和失败重试。

## P7：功能矩阵验收与可发布 RC

### 实施内容

- 对照本计划的移动端范围矩阵，确认订阅、阅读、整理、摘要/翻译、媒体、同步和设置均有实现或明确排除理由；不再以桌面功能数量对齐作为验收目标。
- 完成中、英、日文案校对、动态字体和窄屏适配。
- 完成 TalkBack、触控目标、颜色对比、减少动画和深色模式检查。
- 测试 Android 10、一个中间版本和当前稳定版本，以及至少一种平板尺寸。
- 执行冷启动、大数据库、长文章、长音频和后台刷新稳定性测试。
- 生成签名 Release APK/AAB；签名材料仅存在本地安全环境或 CI Secret。
- 验证从正式 Alpha schema 连续升级到 RC，禁止再次依赖清库。
- 整理隐私说明：本地数据、Feed 请求、AI/翻译第三方请求、凭据和删除方式。

### RC 退出条件

- Rust、Flutter、FRB 和桌面回归全部通过。
- 无阻塞级崩溃、数据丢失、密钥泄露和迁移问题。
- 核心业务场景在真实设备上完成端到端验收。
- Release AAB 可安装、升级、启动并完成订阅到阅读全链路。
- 达到 Google Play 内测准备状态；商店运营材料不属于本计划。

## 4. 公共接口与数据契约

### 4.1 Core 服务

- `SubscriptionService`：文件夹 CRUD、Feed CRUD/移动/发现、刷新、OPML。
- `ArticleService`：分页筛选、搜索、详情、已读/收藏/稍后读、批量已读、全文提取。
- `LibraryService`：标签、规则、高亮、计数和保留策略。
- `AiService`：连接测试、摘要与翻译。
- `SettingsService`：类型化应用、阅读、通知、AI 和同步设置；底层 key/value 仅用于旧数据兼容。
- `ExternalSyncService`：FreshRSS/Miniflux 连接、状态、同步和队列。

### 4.2 跨桥事件

- `RefreshProgress`：开始、单 Feed 完成、整体完成。
- `AiEvent`：摘要文本增量、完成、错误。
- `TranslateEvent`：总批次、批次进度、完成。
- 长任务提供取消句柄。页面销毁只取消 UI 订阅，已进入提交阶段的数据库事务必须完成或回滚。

### 4.3 未来多端同步

`SyncPort` 固定提供：

- `capabilities()`：声明订阅、文章状态、组织、高亮和设置等能力。
- `pull(cursor)`：拉取远端变更并返回新 cursor。
- `push(batch)`：推送本地变更并返回 ack、远端映射和冲突。
- `status()`：返回连接、最近成功时间、待推送量和最后错误。

同步范围默认包含用户意图数据：订阅、文件夹、文章状态、标签关系、规则、高亮和允许同步的设置。

以下数据不进入同步：正文与图片缓存、音频、AI 结果、翻译结果、API Key 及第三方同步凭据。

## 5. Android 平台边界

Rust Core 不直接调用 Android API。Flutter/平台适配层负责：

- 安全凭据存储。
- 系统分享与浏览器打开。
- OPML 文档选择与保存。
- 后台任务调度与通知权限。
- 媒体会话、锁屏控制和播放通知。
- App Link/Deep Link 分发。

平台调用失败统一映射为可恢复错误；业务数据仍由 Core 事务保护。

## 6. 关键风险与控制

- **Core 迁移风险**：以垂直功能切片迁移；每次下沉同时运行 Tauri 回归，避免一次性替换全部后端。
- **数据库风险**：正式 Alpha 后每次 schema 修改都必须有从上一版本升级的测试数据库。
- **FRB 漂移风险**：保持 Rust 与 Dart codegen 版本一致，生成文件提交并在 CI 检查差异。
- **后台限制**：Android 周期任务按尽力而为设计，Core 自己计算到期 Feed，重复唤醒保持幂等。
- **免费翻译端点风险**：Google/DeepL/Bing 作为可切换引擎；失败时保留原文并允许改用 LLM。
- **凭据风险**：数据库只存凭据引用，真实秘密留在 Keystore；日志统一脱敏。
- **外部同步差异**：通过 capabilities 限制 provider 能力，FreshRSS/Miniflux 不支持的实体保持本地。

## 7. 质量门禁

每个阶段至少执行：

```powershell
cargo test -p papr-core
cargo check -p papr-flutter-bridge

Set-Location mobile
flutter test
flutter analyze
flutter build apk --debug
```

涉及桌面适配时追加：

```powershell
Set-Location ..
cargo test -p papr
pnpm test
pnpm build
```

P6 起增加 Release AAB 构建和真实设备验证。无法执行某项检查时，任务交接必须说明原因，不能写成已通过。

高风险场景必须有回归：重复订阅、迁移中断、断网、部分刷新失败、长正文、恶意 HTML、同步重放、规则批量执行、AI 流中断、凭据删除和后台任务重复唤醒。

## 8. Agent 交接模板

每个阶段或子任务结束时，按以下格式写入 Trellis 任务或最终回复：

1. 根因/当前缺口。
2. 已完成能力及未完成能力。
3. 修改文件和每个文件的修改原因。
4. 公共 DTO、数据库迁移、事件或平台接口变化。
5. 实际运行的检查及结果。
6. 已知风险、回滚点和下一任务入口。

只有当前阶段的全部退出条件都有代码、测试或真实设备证据时，才将阶段标记为完成。
