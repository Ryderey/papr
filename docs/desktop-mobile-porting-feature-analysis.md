# Papr 桌面端功能盘点与移动端移植适配分析报告

- 日期：2026-08-22
- 范围：桌面端（`src/` 前端 + `src-tauri/` + `crates/papr-core/`）功能全量盘点，评估各功能移植到 Android/Flutter 移动端的适配性
- 方法：静态代码阅读（未运行测试、未构建、未修改任何代码）
- 关联文档：`docs/flutter-android-rearchitecture.md`、`docs/flutter-android-phased-development-plan.md`

## 结论摘要

Papr 桌面端约 40 项功能中：

- **8 项平台无对应物，无法移植**（托盘、窗口系统、自动更新、快捷键等）
- **5 项与 Android 系统机制冲突，必须整体换方案**（后台调度、音频播放、通知、同步触发、凭据存储）
- **8 项桌面交互范式不适配，建议砍掉或重设计**（hover、右键菜单、拖拽、命令面板等）
- **5 项桌面端本身就是半成品，建议直接砍**

真正值得投入的移植面是**数据与内容能力**（订阅、文章、标签、规则、高亮、全文、翻译、AI、OPML）——这部分与平台无关，移动端 P0–P2 已完成、P3 进行中。官方文档已明确不移植的 4 项（托盘、桌面全局快捷键、Tauri 子 WebView、桌面自动更新器）与本报告档位一完全一致，本报告在此基础上又补充了约 15 项不适合/不建议移植的功能。

## 一、桌面端功能全景

技术栈：Tauri 2（Rust 后端 + React 19 前端），三栏单窗口布局（侧边栏 / 文章列表 / 阅读器）+ 底部全局播放条，无路由；SQLite 本地存储（迁移 v1–v16，WAL，FTS5 全文搜索）。

| 模块 | 桌面端实现 | 移动端现状 |
|---|---|---|
| 订阅管理 | Feed/文件夹 CRUD、右键菜单、拖拽移动、OPML 导入导出、添加源（网页自动发现 + 目录搜索 + RSSHub 展开 + YouTube/Reddit/Mastodon 归一化）、Explore 精选目录、Newsletter(IMAP) 邮箱源 | P1 完成：feed/文件夹/OPML/深链/目录搜索；Newsletter 未做 |
| 阅读体验 | 智能视图（全部/未读/星标/稍后读 + 实时计数）、无限滚动虚拟列表、list/card 视图、hover 预览、单键键盘导航、阅读器（消毒 HTML、懒加载图、YouTube iframe、audio/video enclosure）、全文提取、翻译原文切换条、AI 摘要抽屉、高亮标注、专注模式、网页视图（原生子 webview 叠层） | P2 完成：智能视图、分页、隐藏已读、批量已读、HtmlWidget 渲染、全文提取、阅读设置、系统分享；hover/滚到底已读/专注/网页视图未做 |
| 标签/规则/高亮 | 彩色标签 + 拖拽排序、规则引擎（入库时自动 skip/read/star，预览 + 应用到存量）、高亮 5 色 + 笔记 + 全局浏览（删除有 Undo） | P3 进行中（代码已基本落地） |
| AI | 摘要（多模板、流式、结果持久化）、追问 Q&A、Ask-RAG（FTS 检索 6 篇）、Digest（近 30 篇主题简报）、翻译（LLM/Google/DeepL/Bing）、连接测试、多 Profile 配置 | 未做（P4 计划） |
| 音频 | 全局常驻播放条（HTML5 `<audio>`，无媒体会话）、倍速 0.75–2×、±15/30 秒、跨文章续播 | 未做（P5 计划：MediaSession + 前台服务） |
| 同步 | FreshRSS/Miniflux（GReader 协议）双向：订阅/文件夹/已读/星标，刷新管线尾部自动触发 | 未做（P6 计划） |
| 后台 | 常驻调度器：启动 8s 后每 60s tick，条件 GET（ETag/Last-Modified）、并发 6（可调 1–16）、保留期清理、newsletter 轮询、失败记录 fetch_error | 无调度器（P6 计划换 WorkManager） |
| 通知 | 系统通知（开关/声音/夜间免打扰）、Dock 徽标、应用内 toast（带 Undo） | 有 SnackBar；系统通知未做 |
| 桌面集成 | 托盘（未读数/刷新/全部标读/设置/退出）、自动更新（GitHub release）、开机自启、`papr://subscribe` 深链（配合浏览器扩展）、窗口状态记忆、macOS 特调 | 深链已做；其余不移植 |
| 设置中心 | 10 分区：常规/外观/阅读/订阅/Filters/同步/快捷键表/通知/高级（AI、存储维护、网络代理、危险区）/关于 | 部分：主题/语言/阅读设置/刷新间隔展示 |
| 命令面板 | ⌘K 三合一（动作/feed/文章搜索） | 未做 |
| 本地化 | 中/英/日（i18next） | 中/英/日（l10n，zh/ja 各差 10 个键未译） |
| 半成品 | Send to Kindle（lettre 依赖声明但零接线）、AI Ask/Digest（后端齐备但前端无 UI 入口）、内容去重（实验开关） | — |

## 二、不适合移植的功能清单

### 档位一：平台无对应物，无法移植（8 项）

| 功能 | 桌面形态 | 为什么不适合 |
|---|---|---|
| 系统托盘 | 托盘菜单（未读数/打开/刷新/全部标读/设置/退出）、左键弹出、菜单栏未读数 | Android 无任务栏/托盘概念；移动端对应物是通知栏常驻通知 + 快捷操作，语义完全不同。桌面"驻留托盘以便后台刷新"的整个常驻模型与 Android 生命周期冲突（见档位二第 1 条） |
| 窗口系统 | 默认 1280×820、最小 920×560、overlay 标题栏、traffic lights、窗口状态记忆、macOS WKWebView 去白底 | Android 无窗口概念，全部无意义 |
| 开机自启 | autostart 插件（macOS LaunchAgent / Windows 注册表） | Android 不允许应用随意自启；等效物是 WorkManager 等系统调度后台任务 |
| 应用内自动更新 | updater 插件从 GitHub 拉签名安装包 + `relaunch()` | Android 更新只能走应用商店/AAB 分发通道，签名与分发模型完全不同，代码不可复用（官方文档已明确不移植） |
| Dock/任务栏徽标 | notify.rs 设置 Dock 未读数 | Android launcher 角标依赖各厂商实现，能力不可控，不建议做 |
| 子级 WebView「网页视图」叠层 | Tauri unstable API 在阅读区叠加子 webview，ResizeObserver 同步位置 | Android 应用内嵌原文页需换 webview_flutter 或交给系统浏览器；"边阅读边叠原文页"是桌面宽屏交互，手机全屏模型下不成立（官方文档已明确不移植） |
| 快捷键体系 | 全局 ⌘K/⌘, /⌘R + 单键 j/k/s/b/i/f/u/v/a、方向键/Home/End、Escape | Android 无常驻键盘；外接键盘场景过小众。整套"键盘驱动阅读"范式必须重构为触控动作（官方文档已明确不移植） |
| 多选 | 桌面端本身没有多选（仅"全部标已读"） | 无需移植；移动端反而已做了批量已读，比桌面更进一步 |

### 档位二：与 Android 系统机制冲突，必须整体换方案（5 项）

这些功能"换一层底座"可做，但**不能照搬桌面代码**，属于机制替换而非代码移植：

| 功能 | 桌面形态 | 移动端方案 |
|---|---|---|
| 常驻后台调度器 | 每 60s tick 轮询到期 feed、条件 GET、并发限流、保留期清理、newsletter 轮询 | Android 的 Doze/App Standby 禁止常驻轮询；必须换 WorkManager 周期任务，由系统唤醒 → core 判断到期 feed → 幂等刷新。桌面"应用开着才刷"要反转为"系统唤醒才刷"（P6 已定义） |
| 音频播放器 | HTML5 `<audio>`，无媒体会话，锁屏即断 | 播放器 UI 可重做，但后台播放/锁屏控制/蓝牙按钮必须靠 MediaSession + 前台服务 + 通知，基础设施全部重做（P5 已定义） |
| 系统通知 | notify.rs：新文章通知/开关/声音/夜间免打扰 | 语义可移植，实现全重做：通知渠道、Android 13+ 运行时权限、通知图标与批量汇总（P6 已定义） |
| FreshRSS 同步触发 | 每次刷新管线尾部自动跑双向同步 | 同步协议逻辑可下沉 papr-core，但触发时机在移动端只能手动 + 低频 WorkManager；且桌面明文存 `freshrss_auth` token，移动端必须进 Keystore（P6 已定义） |
| 凭据明文存储 | IMAP 密码明文入库（迁移 v10）、AI API Key 存 settings KV | 移动端一律 Keystore/加密存储（P4/P5 已列入计划） |

### 档位三：桌面交互范式不适配，建议砍掉或完全重设计（8 项）

| 功能 | 建议 | 理由 |
|---|---|---|
| hover 悬浮预览 | 砍 | 无鼠标；手机上点开即详情，650ms 悬停卡片无信息增量且易误触 |
| 右键菜单体系 | 重设计 | 侧栏/列表/正文动态菜单（保存图片、复制图址、AI 等）整体由长按菜单替代。正文图片经 `fetch_image` 带 Referer 防盗链抓取转 data:URL 那套机制，移动端直接用 `Image.network` + 失败占位即可，不值得照搬 |
| 拖拽排序/移动 | 不照搬 | 触控长按拖拽精确度差；移动端已用"长按 → 移动 sheet/上移下移"替代（标签/文件夹均如此） |
| 命令面板 ⌘K | 降级或砍 | 无键盘触发；三合一（动作/feed/搜索）在手机上可降级为浮层搜索，但九个动作的键盘流价值大减 |
| 选中文字浮动取色条 | 不照搬 | 桌面鼠标选区工具条；Android `SelectionArea` 自定义菜单已实现等价能力（详情页已落地） |
| 滚到底自动标已读 | 默认关闭 | 触屏滚动惯性大，长文阅读极容易误触发 |
| 专注模式（f 键） | 砍 | 桌面语义是"隐藏侧栏进入全键盘阅读"；手机全屏本是常态，平板可用分屏代替 |
| YouTube iframe 内嵌 | 改外链 | 需要额外引入 webview_flutter；桌面"边读边看"的伴随观看在手机上不成立，应交给 YouTube App |

### 档位四：桌面端半成品/低价值，建议直接砍（5 项）

| 功能 | 判断 |
|---|---|
| Send to Kindle（F8） | 桌面端就是死代码：`lettre` 依赖已声明但没有任何命令使用它，无 UI 入口。建议直接砍，不进移动端清单 |
| AI Ask / AI Digest | 后端命令齐备但桌面前端无任何 UI 入口（README 声称支持，属"待接线"）。移动端 P4 需重新评估产品价值，没有明确场景就砍 |
| RSSHub 自建实例配置 | `rsshub://` 短链展开依赖用户自建服务，小屏配置链路长。低优先级 |
| Newsletter/IMAP 订阅 | 桌面可行（验证凭据 + 摄入），但既有实现明文存密码，且表单（主机/端口/账号/密码）在小屏上繁琐；P5 计划已排且注明密码进 Keystore。属于"可移植但要重做安全与触发" |
| 内容去重（实验开关） | 桌面实验特性，无验证数据支撑，不建议随移植投入 |

## 三、其余功能的移植原则

**适合直接移植（数据/内容能力，与平台无关）**：智能视图与计数、文章分页列表、全文搜索、标签/规则/高亮（P3 进行中）、全文提取、阅读设置、多语言/主题、OPML（已完成）、`papr://` 深链（已完成）、翻译与 AI 摘要（P4，UI 形态改为全屏/底部 sheet，流式与缓存逻辑可直接复用 papr-core）。

**移植时的统一提醒**：

- 移动端设置项中"快捷键速查表、托盘相关、自动更新、开机自启"可直接从设置中心移除；"自定义代理、存储统计/VACUUM、清空数据"可做但优先级低（P6）。
- 桌面端 AI、同步、调度逻辑目前都在 `src-tauri/` 侧，papr-core 里已有 v16 同步基建（`change_log`/`sync_cursor`/`remote_id_map`）但未被消费——P4/P6 下沉时要避免与旧 `sync_queue` 双轨并存。
- 移动端 l10n 的 zh/ja 各有 10 个键未翻译（P7 文案校对已列入）。

## 四、总结

1. 官方文档（`docs/flutter-android-phased-development-plan.md:34`）已明确不移植的 4 项——托盘、桌面全局快捷键、Tauri 子 WebView、桌面自动更新器——与本报告档位一完全一致；本报告在此基础上又补充了约 15 项不适合/不建议移植的功能。
2. 移动端移植的正确基线是**数据与内容能力**，不是桌面交互范式（键盘、hover、右键、拖拽、托盘常驻）。凡依赖鼠标、键盘、窗口、常驻进程的功能都应排除或重设计。
3. 需要为 Android 专门建设而非移植的四大机制：后台调度（WorkManager）、音频播放（MediaSession + 前台服务）、凭据安全（Keystore）、文件访问（SAF）——分阶段计划 P4–P6 已覆盖，与本文档结论吻合。
