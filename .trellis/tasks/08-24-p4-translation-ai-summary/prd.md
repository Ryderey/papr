# P4 翻译与 AI 摘要

## Goal

把桌面端已验证的摘要、HTML 分块翻译和流式协议下沉到 `papr-core`，通过 FRB 在移动阅读器中提供摘要与翻译，并由 Android Keystore 保存 API Key。

## Requirements

1. 支持 Anthropic Messages 与 OpenAI Chat Completions 兼容端点，多 Profile、模型、Base URL、认证方式和连接测试。
2. SQLite 只保存 Profile 元数据与 Keystore 引用；密钥不得进入数据库、日志、错误、备份或同步。
3. 摘要支持模板、流式增量、缓存、重新生成、取消、重试与针对当前摘要的连续追问；切换文章必须隔离状态。
4. 翻译支持 LLM、Google、DeepL、Bing，按 HTML 块处理并保留链接、图片、代码块与层级；缓存最近目标语言。
5. Core 拥有 HTTP、SSE、分块、验证和缓存写入；Flutter 只编排页面状态和稳定错误码。
6. 明确排除脱离当前摘要的文章全文问答、全局 Ask/RAG、Digest 与向量数据库。
7. 移动端 AI 摘要使用独立全屏页面；从阅读器进入，返回后恢复正文原滚动位置，不使用会挤压正文的并排抽屉。
8. 摘要页命中完整缓存时直接展示且不联网；无缓存时进入页面自动开始流式生成；重新生成必须由用户显式触发；离开生成中的页面时取消请求且不保存残缺结果。
9. 连续追问只使用当前完整摘要与本次问答历史作为上下文，不读取或检索文章全文；问题超出摘要信息时必须明确说明无法从摘要判断。
10. 追问记录只保存在当前摘要页面内存中；退出页面、切换文章或重新生成摘要后清除，不写入 SQLite、备份或同步负载。
11. 每篇文章只缓存最近一次完整摘要及其 `ai_summary_template`；切换模板只更新待生成选项，用户显式重新生成且完整成功后才原子替换摘要与模板元数据。
12. 摘要与追问输出语言跟随应用界面语言，并将最近成功摘要的语言保存为 `ai_summary_lang`；切换界面语言不得自动重新生成。
13. AI 配置列表的新增入口位于右下角悬浮“+”，与其他列表页的新增入口保持一致；每个已保存 Profile 提供连接探测。探测必须复用摘要的 Provider/SSE 请求路径、只报告稳定结果、不读写文章或摘要缓存，也不得持久化或回显密钥。
14. 摘要只允许一个 AI Profile 处于生效状态。配置弹窗外的列表启用开关切换生效 Profile；开启任一项时必须原子地关闭其他 Profile。用户也可关闭当前生效项，此后不得回退到列表中其他 Profile，摘要页应要求先启用一个配置。

## Acceptance Criteria

- [ ] HTTP/SSE 测试覆盖分片、超时、取消、限流、非法响应和中途失败。
- [ ] 翻译后 HTML 结构与不可翻译节点保持正确，失败保留原文和旧缓存。
- [ ] API Key 不出现在 SQLite、日志、错误消息或同步负载。
- [ ] 摘要/翻译在文章切换、重试、取消后不串状态。
- [ ] 摘要缓存命中不发起网络请求，取消或失败不覆盖旧缓存，只有完整成功才替换缓存。
- [ ] 缓存摘要显示其实际模板；切换模板不自动请求，重新生成失败时摘要与模板元数据均保持旧值。
- [ ] 缓存摘要显示其生成语言；切换界面语言后旧缓存仍可读取，但只有用户显式重新生成才替换摘要、模板与语言。
- [ ] 连续追问按当前文章和当前摘要隔离，不得进入全局文章检索路径。
- [ ] 追问请求不携带文章正文；超出摘要内容的问题返回明确的边界提示，不编造正文细节。
- [ ] 退出摘要页后重新进入只恢复摘要缓存，不恢复此前追问；SQLite 与同步负载中不存在追问记录。
- [ ] 打开和关闭全屏摘要页不会改变正文滚动位置，摘要流式输出不挤压或重排正文。
- [ ] FRB 生成幂等，Core/Bridge/Flutter/桌面回归与 Debug APK 通过。
- [ ] 已保存 Profile 的连接探测能正确区分密钥、认证、网络与响应错误；成功探测不得改变摘要缓存。
- [ ] 多 Profile 场景始终至多有一个生效项；切换生效项和关闭当前项在重启后保持，摘要只使用该项，全部关闭时不发起网络请求。

## Dependencies / Out of Scope

依赖 P3 归档。遵守父任务“明确排除”清单；不借本任务恢复 Ask、RAG 或 Digest。
