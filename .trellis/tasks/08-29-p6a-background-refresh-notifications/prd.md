# P6A 后台刷新与新文章通知

## Goal

让 Android 在应用未打开时仍能按用户的刷新间隔尽力刷新到期订阅，并在获得权限且未处于夜间免打扰时，用一条汇总通知提示新文章。

## Background

- Android 后台执行可能被 Doze、电量策略和厂商限制延迟，因此不承诺分钟级准时。
- 当前 Core 的 `refresh_feeds` 总是读取全部订阅，`RefreshOptions.force` 尚未参与到期选择；桌面端已有按全局/单订阅间隔计算到期订阅的成熟语义。
- 全局或单订阅使用 `525_600` 分钟表示关闭自动刷新；手动刷新不受该设置限制。
- Android 周期任务最短间隔为 15 分钟。小于 15 分钟的用户设置仍由 Core 判断到期，平台只按 15 分钟唤醒。
- 桌面通知的既有夜间免打扰窗口为 22:00–08:00，移动端沿用该固定窗口。

## Requirements

1. Core 根据全局 `refresh_interval_min`、单订阅覆盖值和 `last_fetched_at` 选择到期订阅；从未抓取的订阅立即到期，关闭自动刷新的订阅不进入后台刷新。
2. `force=true` 的手动刷新保持刷新指定订阅或全部订阅的行为；`force=false` 才使用到期选择，不能改变现有手动刷新入口。
3. 后台刷新继续使用 ETag/Last-Modified 条件请求、文章唯一键和逐订阅错误记录；单个订阅失败不阻断其他订阅。
4. Android 使用唯一周期任务、联网约束和退避策略。关闭自动刷新时取消周期任务，修改间隔时更新同一任务，不创建重复任务。
5. 后台执行通过独立 Dart isolate 初始化现有 FRB/Core，不在 Worker、Flutter UI 或通知层复制抓取和入库规则。
6. 设置页允许开启/关闭自动刷新、选择 15–120 分钟的刷新间隔、开启/关闭新文章通知和夜间免打扰。
7. 新文章通知默认关闭；用户主动开启时才请求 Android 13+ 通知权限。拒绝或撤销权限只影响通知，不影响后台刷新。
8. 新增文章数大于零且通知已启用、权限已授予、当前不在 22:00–08:00 免打扰窗口时，只显示一条本地化汇总通知。
9. 后台任务和通知失败不得回滚已成功写入的文章；错误不得暴露订阅正文、URL、凭据或第三方响应。
10. P6A 不包含 FreshRSS/Miniflux、精确定时、常驻前台服务、通知动作、可配置免打扰时间段、Dock/角标、newsletter 轮询或高级并发/代理面板。

## Acceptance Criteria

- [ ] Core 测试覆盖从未抓取、尚未到期、刚好到期、单订阅覆盖、关闭哨兵值和异常全局设置回退。
- [ ] 手动 `force=true` 与后台 `force=false` 的选择行为有回归测试，重复刷新不产生重复文章。
- [ ] 应用重启后只存在一个周期任务；间隔更新、关闭和重新开启均符合设置，任务仅在联网时执行。
- [ ] 后台任务在应用退到后台或进程结束后能初始化同一个数据库并完成刷新；无到期订阅时不发网络请求和通知。
- [ ] 通知关闭、权限拒绝/撤销、零新增和夜间免打扰均不显示通知；正常场景只显示一条本地化汇总通知。
- [ ] 单订阅失败、通知失败和系统延迟不会破坏已入库数据，前台重新打开后能看到后台新增文章和错误状态。
- [ ] `cargo test -p papr-core`、`cargo check -p papr-flutter-bridge`、`flutter test`、`flutter analyze` 和 Debug APK 构建通过。
- [ ] 在 Android 虚拟机或实体机完成一次立即调试任务、一次进程结束后的后台刷新、一次权限拒绝和一次免打扰验证并记录结果。
