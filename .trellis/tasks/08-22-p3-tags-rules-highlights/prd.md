# P3 标签、规则与高亮

## Goal

让 Android Flutter 客户端完成本地文章的个人整理：标签、入站过滤规则和可持久化的阅读高亮，所有数据规则、事务和同步变更日志均由 `papr-core` 负责。

## Confirmed Facts

- P2 已提供只读标签筛选和 `tags` / `article_tags` / `rules` / `highlights` 表；本阶段不需要新迁移。
- 桌面端已有可迁移的标签 CRUD、规则匹配/预览/应用和高亮数据逻辑，位于 `src-tauri/src/db.rs`。
- 规则字段为 `title`、`author`、`content`、`any`；动作为 `skip`、`read`、`star`；同一匹配器必须用于入站、预览和既有文章应用。
- 高亮锚点由 `quote`、`prefix`、`suffix`、`text_offset` 组成，重新打开文章时需优先偏移定位，失败后使用上下文重定位，并保留无法定位的记录。
- Flutter 正文由 `flutter_widget_from_html_core` 渲染，当前页面没有高亮创建交互；无现成 WebView 或第二套 HTML 渲染器。

## Requirements

1. 保留已有标签数据与只读筛选兼容性；Flutter 移动端本阶段不提供标签创建、重命名、删除、颜色、排序或文章关联编辑。
2. Core 仍保持标签删除只删除标签与关联关系、不删除文章的既有数据语义；移动端不暴露对应写入入口。
3. 规则支持创建、编辑、删除、启停、Feed 范围、字段、关键字和动作；规则顺序保持稳定。
4. 规则预览、对已有文章应用与新文章入站处理复用完全一致的匹配语义；`skip`、`read`、`star` 的文章写入均保持事务性和同步日志一致性。
5. 阅读器必须支持正文长按选择文字后直接创建高亮，并支持颜色、笔记更新、删除、按文章浏览与全部浏览；创建时保存可重定位锚点。
6. 阅读器重开后根据锚点重新定位高亮；无法定位时仍显示记录和提示，不丢失用户笔记。
7. Flutter 仅经 Repository/Provider 调用 FRB；错误使用稳定码并本地化；写入使用乐观更新与失败回滚。文章页星形按钮对应“星标”，书签按钮对应“稍后读”，写入成功后退出并重新进入文章仍保持状态。

## Acceptance Criteria

- [ ] 标签 trim、大小写重复、颜色、排序、关联和删除语义均有 Core 回归测试；任一写入失败不会留下 change_log 半写入。
- [ ] 规则预览数量/示例和实际应用对象一致；Unicode、LIKE 通配符、Feed 范围、停用与重复应用语义被覆盖。
- [ ] 新文章与既有文章使用同一规则匹配器；跳过规则不会清理收藏、稍后读或含高亮的文章。
- [ ] 高亮的创建、笔记/颜色更新、删除、文章级/全局列表和锚点重定位均有 Core/Flutter 测试。
- [ ] Flutter 可完成规则管理、高亮创建与浏览；星标/稍后读跨页面重开后保持状态，写入失败能恢复可见状态并提示；设置中不显示标签管理入口。
- [ ] FRB 生成幂等，Core、Bridge、桌面回归、`flutter analyze`、`flutter test` 和 Debug APK 构建通过。
- [ ] 手机与平板上的正文长按/选择高亮、规则预览/应用、旋转和进程恢复通过实体机验收。

## Out of Scope

- AI 摘要、翻译、问答和 Digest（P4）。
- Podcast、Newsletter、后台媒体能力（P5）。
- 外部同步协议和后台刷新（P6）。
- 新 WebView、第二套数据库、第二套状态管理或新的第三方依赖。
- 移动端的标签编辑与管理入口，包括文章阅读器与设置页；本轮移除，后续有明确需求时再重新设计。

## Product Decision

- 高亮采用完整阅读器交互：用户长按选择正文文字后直接创建，不使用手动输入引用文本的降级流程。
